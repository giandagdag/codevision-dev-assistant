Project charter Envisioned

What CodeVision is, what it isn't, and how it's built.

0% of charter limit

Purpose

One paragraph. What CodeVision is for.

CodeVision helps the bank modernize hostcentric applications. It turns specifications, COBOL, RPG and CL source, and Control-M job flows into a searchable knowledge base, with AI tools built on top.

Scope

What requests should and shouldn't touch.

✅ In scope
  • Tools that analyze legacy source and specs
  • Documentation generation
  • Knowledge base ingestion and search
  • CodeVision's own screens and tooling
🔴 Out of scope
  • Customer-facing features
  • Changes to hostcentric production systems
  • Processing live customer data

Architecture principles

How CodeVision is built. One principle per line.

  • Data classes live in pydantic_classes/
  • UI styles come from shared_styles.py brand constants
  • Reuse helpers in tools/ before writing new ones
  • Paths and settings come from config

Constraints

Hard limits no request can break.

  • Internal LLMs only (Qwen, Llama)
  • Python only
  • Approved libraries only

Glossary

CodeVision's own terms, so Qwen names and reads them consistently.

TermMeaning
CapabilityA CodeVision feature, e.g. Source Compare
Application onboardingAdding a legacy application's specs and source into CodeVision
HostcentricLegacy applications written in COBOL, RPG or CL
Control-M job flowA scheduled sequence of batch jobs
